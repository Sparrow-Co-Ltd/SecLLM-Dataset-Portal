데이터셋Dataset

레코드 하나는 취약점 정보(input)와 그것을 해결하는 코드 수정(output)의 쌍입니다. 라인 번호는 모두 원본 코드 기준입니다. Each record pairs the finding (input) with the change that resolves it (output). All line numbers refer to the original file.

레코드에 담긴 것What a record holds

  • 취약점이 발생한 전체 소스 파일과 발생 라인The full source file and the reported line
  • 취약점 유형명과 설명 (한국어·영어)Defect type and description in Korean and English
  • 같은 유형의 위험 예시와 안전 예시 코드Vulnerable and safe example code for that type
  • 분석기 추적 경로 — source → branch → sinkThe analyzer trace: source, branch, sink
  • 재검증을 통과한 코드 수정 목록The verified list of code modifications

수집 방식How it is built

  • 허용적 라이선스로 배포된 공개 코드 코퍼스에서 언어별 소스 추출Language-wise extraction from a permissively licensed public code corpus
  • SAST CLI로 청크 단위 스캔 후 결과 증분 집계Chunked scanning with a SAST CLI, results aggregated incrementally
  • CWE·OWASP 매핑과 위험도별 커버리지 산출CWE and OWASP mapping, with coverage tracked by severity
  • 패치 적용 후 재분석에서 해결이 확인된 수정만 수록Only patches confirmed resolved by re-analysis are included

라벨은 모두 정적분석기의 판정이며 실행으로 확인한 결과가 아닙니다. 오탐이 포함될 수 있고, 조치 코드는 같은 분석기 재검사로만 검증했습니다. Labels come from a static analyzer, not from execution. False positives are possible, and patches are verified only by re-running the same analyzer.

모델Model

큰 모델을 그대로 쓰는 대신, 조치 제안 능력만 작은 모델로 옮겨 자체 서버에서 돌릴 수 있게 만드는 것이 목표입니다. Rather than depend on a large model, the goal is to move remediation ability into a small one that runs on your own server.

파인튜닝Fine-tuning

1단계는 교사 에이전트 궤적 2,205개로 LoRA SFT, 2단계는 SAST 탐지 10,390건 풀에서 GRPO(GRPO-LEAD 길이·난이도 보정)입니다. 두 단계를 병합해 전체 가중치로 배포합니다. 이전 버전은 GRPO 180스텝 LoRA 어댑터입니다.Stage 1 is LoRA SFT on 2,205 teacher agent trajectories; stage 2 is GRPO with GRPO-LEAD length and difficulty shaping over a pool of 10,390 SAST findings. Both stages are merged into full weights. The earlier release was a LoRA adapter at GRPO step 180.

에이전트 파이프라인Agent pipeline

두 단계 그래프입니다. 탐색 단계가 근거를 모으고, 수정 단계는 자유 텍스트 대신 편집 도구 호출로만 코드를 바꿉니다. A two-stage graph: exploration gathers evidence, and the fix stage changes code only through an edit tool, never as free text. 

START → explore → fix_branch → END

explore

  • 언어를 판별하고 전체 코드를 AST 청크로 분할Detect the language and split the file into AST chunks
  • 문제 라인을 포함한 청크와 이를 감싸는 클래스·함수 심볼 확인Find the chunk holding the reported line and its enclosing class and function
  • 추적 경로 이벤트로 source → sink 경로 구성Rebuild the source-to-sink path from trace events
  • 식별자의 선언 지점과 변경 지점 추적Track where identifiers are declared and modified

fix_branch

  • 이슈 메타데이터·코드 청크·분석 문맥·예시 코드를 프롬프트로 구성Compose the prompt from issue metadata, code chunks, analysis context, and examples
  • 모델이 편집 도구를 강제 호출하도록 설계Force the model to call the edit tool
  • 최대 3회 피드백 루프로 자체 검증, 적절하면 조기 종료Up to three self-check rounds, stopping early when the fix holds
  • 편집 결과를 삭제·추가 연산으로 변환하고 6종 검증Convert edits into delete and add operations, then run six checks

코드 청킹Code chunking

tree-sitter 기반 청킹 라이브러리를 포크해 C·C++·Go·JavaScript를 추가했습니다. 청크가 기준 길이를 넘으면 하위 노드로 재귀 분할합니다.A fork of a tree-sitter chunker adds C, C++, Go, and JavaScript; oversized chunks split recursively at child nodes.

표준 연동Standards

SARIF 2.1.0으로 다른 분석 도구의 결과도 받습니다. 공식 스키마 적합성과 왕복 변환 일치를 확인했습니다.SARIF 2.1.0 intake accepts results from other analyzers, validated against the official schema with round-trip checks.

평가 체계Evaluation

재스캔만으로는 탐지 회피나 의미 없는 변경을 걸러낼 수 없고, 모델 심사만으로는 취약점이 남은 수정을 놓칩니다. 두 축을 합쳐 해결 여부를 확정합니다. Re-scanning alone cannot tell a real fix from evasion or a no-op; a model judge alone misses patches that leave the defect in place. The two axes are combined.

remediation_outcome

패치를 적용한 뒤 재스캔에서 대상 취약점이 더 이상 검출되지 않는지 확인하는 규칙 기반 판정입니다.A rule-based check: after the patch, the target finding no longer appears in the re-scan.

remediation_quality

규칙으로 가리기 어려운 보류 사례만 모델 심사로 해소합니다. 아래 다섯 항목의 가중합입니다.A model judge resolves only what rules cannot settle, scoring the five criteria below.

평가 항목Criterion 가중치Weight 확인하는 것What it checks
fix validity0.35수정이 취약점을 실제로 없애는가Does the change actually remove the defect
no evasion0.25탐지만 피해 간 변경은 아닌가Is it merely evading detection
localization0.15문제 지점을 정확히 짚었는가Is the right location targeted
minimality0.15필요 이상으로 코드를 바꾸지 않았는가Is the change no larger than needed
exploration0.10근거를 충분히 탐색했는가Was the evidence explored properly

재현성 장치Reproducibility

  • 패치가 원본을 덮어쓰지 않도록 적용 순서를 고정Patch application order is fixed so originals are never overwritten
  • 고비용 모듈은 실행 1회를 보장해 중복 비용 차단Expensive modules are guaranteed to run exactly once
  • 공유 자원 충돌을 5단계 파이프라인으로 자동 조정Shared-resource contention is handled by a five-stage pipeline
